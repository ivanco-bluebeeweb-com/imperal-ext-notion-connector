# Notion Connector — что видит и чем управляет пользователь после подключения

## 1. Целевой пользователь
Операционный/продуктовый менеджер, использующий Notion как единый рабочий хаб (базы
данных, документация, вики) для команды.

## 2. Момент истины после подключения
Сразу после `connect_workspace` — `check_access`: честный отчёт, какие страницы/базы
данных реально видит интеграция, плюс `browse` — верхнеуровневая структура воркспейса.

## 3. Что пользователь видит
- Структуру воркспейса (страницы верхнего уровня и вложенность) — `browse`.
- Содержимое любой страницы (текст, блоки) — `read_page`.
- Строки любой базы данных со значениями всех колонок — `query_database`.
- Список доступных баз данных — `list_databases`.
- Людей и ботов, у которых есть доступ к воркспейсу — `list_users`.
- Комментарии на странице — `list_comments`.

## 4. Чем пользователь может управлять
- Создавать страницу — как самостоятельную, так и строкой в базе данных —
  `create_page`.
- Создавать целую базу данных с нужными колонками — `create_database`.
- Обновлять заголовок страницы или значения её свойств (если это строка базы) —
  `update_page`.
- Добавлять контент на существующую страницу — `update_page_content`.
- Перемещать страницу под другого родителя — `move_page`.
- Отправлять в корзину / восстанавливать страницу — `trash_page`.
- Искать по всему воркспейсу по названию — `search`.
- Комментировать страницу — `add_comment`.

## 5. "Вау"-момент для демо потенциальному клиенту
"Смотри — говорю Webbee: 'найди базу с задачами команды и добавь туда новую задачу на
завтра'. Она находит через `list_databases`, определяет структуру колонок и создаёт
`create_page` строкой с правильными значениями — без открытия Notion."

## 6. Что делает это "заточенным под него"
`query_database` читает РЕАЛЬНУЮ схему колонок конкретной базы данных клиента (какие
свойства он сам настроил — статус, приоритет, дедлайн, кастомные теги) — Webbee не
навязывает свою структуру, а работает с существующей.
