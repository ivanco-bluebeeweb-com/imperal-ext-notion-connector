## Прогон 2026-08-20 — Часть D (Deploy Verification / Idempotency / Security-SSRF / Regression grep)

**D1 (Deploy Verification):** не применялось — код приложения не менялся (только тесты), деплой не требуется.

**D2 (Idempotency):** добавлен 1 тест. `trash_page` PATCH'ит `in_trash=true` — Notion принимает повторную установку уже истинного поля как обычный успех, не ошибку. Тест подтверждает: два вызова `trash_page` подряд на одной странице остаются успешными оба раза. Попутно найден и исправлен баг в САМОМ тесте (не в приложении): резолюция воркспейса кэшируется в `ctx` после первого вызова, поэтому лишний замоканный `GET /users/me` на втором вызове "съедался" неправильным HTTP-вызовом и ломал тест — поправлено, приложение работало верно с самого начала.

**D3 (Security/SSRF):** подтверждено — ни одна `@chat.function` не принимает пользовательский URL для fetch; поля `url` на `NotionObject`/`PageContent`/`DatabaseRow` — это собственные read-only ссылки Notion на страницы, только выходные данные. Все обращения идут через фиксированную константу `NOTION_API` (`api.notion.com`). Добавлен 1 regression-тест на эту константу.

**D4 (Regression grep):** нет новых находок специфичных для этого приложения сверх `Docs/known-bug-patterns.md`.

**Итог:** 131/131 тестов зелёные (было 125). Реальных багов в приложении не найдено (один баг в собственном тесте найден и исправлен в процессе).

## Прогон 2026-08-19

**Существующее покрытие до PST:** 119 тестов в 8 файлах — глубокое
покрытие search, чтения страниц, создания баз данных, комментариев,
строк, перемещений и корзины, включая явные регрессионные тесты на
типизацию `parent` (page vs database asymmetry). Аудит по точному имени
`@chat.function` нашёл **4 функции, никогда не тестировавшиеся**:

`list_comments`, `list_databases`, `list_users`, `update_page_content`.

**Новый файл:** `tests/test_pst_scenarios.py` — 10 сценариев: happy path
для каждой из 4 функций плюс blocked (нет токена) для `list_databases` и
`list_users`, error (страница не найдена) для `list_comments`, error
(пустой текст отклоняется с `NOTION_VALIDATION_FAILED`) и два happy пути
(`position=end` по умолчанию не шлёт override, `position=start` шлёт
`{"type": "start"}`) для `update_page_content`. Каждый проверяет не
только успех вызова, но и форму реального HTTP-запроса (правильный
фильтр объекта, правильный `block_id`, правильный `position`).

### Результат

129/129 тестов зелёные (119 существующих + 10 новых). **Реальных багов в
приложении не найдено.**
